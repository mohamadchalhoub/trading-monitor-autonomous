# Project status — the single authoritative reference

This is the canonical index for "what phase is this," "is it actually done," and "how do I know."
Read this first; the per-module `*_SPEC.md` files are the detailed design record for each piece,
not the roadmap.

## Why this document exists

Two different phase numberings exist in this repository, and neither is wrong so much as they
answer different questions:

- **`Trading-Behavior-Monitor-Plan.pdf`** (repo root) is the original master plan, written before
  any code existed. Its own sequence is P1 MT5 proof-of-concept, P2 ingestion, P3 minimal status
  page, P4 Telegram infra, P5 health monitoring, P6 analytics, P7 rules, P8 AI, P9 full dashboard,
  P10 XTB importer, P11 production deployment.
- **The individual `*_SPEC.md` files** were written and built in a *different* order than the
  plan's own numbering (health monitoring shipped as "Phase 7," not P5; the dashboard shipped as
  "Phase 9" but XTB shipped as "Phase 8," not P10) — and nothing is ever labeled "Phase 10" at all.

Neither history is a mistake. The plan was always going to be reordered as real priorities emerged
(the dashboard came after XTB in practice, not before, because XTB needed the account model the
dashboard also needed). But it means "Phase 8" in this repo answers *"which spec file"*, not
*"which step in the master plan."* This table is the crosswalk. Going forward, cite this
document's **Build order** column, not a bare "Phase N," when precision matters.

## Status legend

Every row below uses exactly one of these five labels. They are not a maturity score — a component
can be `TESTED ONLY` and still be exactly correct; the label says what kind of evidence exists for
it, not how good it is.

| Label | Means |
|---|---|
| **IMPLEMENTED** | The code exists and typechecks/builds; no test or real-world run has exercised it yet. |
| **TESTED ONLY** | Covered by automated tests (vitest against a real disposable Postgres/Redis), never run against real external data or infrastructure. |
| **VERIFIED WITH REAL DATA** | Actually exercised against a real MT5 account, a real Telegram bot, or another real external system, at least once, with the result observed. |
| **NOT YET VERIFIED** | A specific, named gap — usually because it needs something only you can provide (a real file, a credential, real infrastructure). |
| **PRODUCTION BLOCKER** | Must be resolved before this is safe or complete to run unattended / expose beyond a trusted local network. |
